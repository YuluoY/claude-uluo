# 讲解方法：怎样讲得让人容易懂

好视频的核心是讲清楚，而不是特效。下面几条适用于所有类型；各类型包的 `GENRE.md` 在此基础上给出具体结构。

## 建构的顺序：现象 → 原理 → 术语 → 反例

1. **现象**：从观众见过、能感到疑惑的具体场景开始，或一个能手算的小例子。先让人想知道答案。
2. **原理**：用一个关系讲清机制（先后、因果、对比、组成、变化），一次只讲一个关系。
3. **术语**：观众看懂了再给名字。先名词后解释，观众要一边记名词一边理解，负担翻倍。
4. **反例与边界**：什么时候不成立、常见误解。讲完反例，观众才真正知道这个概念的边界在哪。

最后用一句话或三个关键词小结。

## 先定关系，再选画面

写每个镜头时先回答：**这一镜要让观众看懂什么关系？**把答案写进 storyboard 的 `intent`，再选最能表达这个关系的画面形式：

| 关系 | 画面形式 |
|---|---|
| 并列的几点 | 要点逐条出现 |
| 先后、因果、流程 | 步骤框 + 箭头，当前步骤高亮 |
| 两者差异 | 左右对比 |
| 组成、层级 | 树、嵌套框 |
| 多少、大小 | 数字、柱状图（必须有出处） |
| 随时间变化 | 时间线、状态随步骤变化 |
| 过程中的状态 | 数据结构可视化 + 代码逐行（算法类） |
| 一句要记住的话 | 大字，关键词变色 |

反面例子：为了“好看”在讲流程时放一张氛围图、讲对比时只放两段文字。画面和关系对不上，观众就只能靠听。

## 画面从哪来

写完 `intent` 之后，按第 0 步问到的能力选来源，顺序固定：

1. 代码、数据、数字、图解，或必须卡在某个词上：React 场景。
2. 不需要排字的静图，且简报里生图有工具名：无字图，`image`。
3. 实拍或气氛运动，且简报里生视频有工具名：`public/clips/`，`clip`。
4. 其余用场景。

配音看生语音那一行：有工具名用 `external`，没有用 edge-tts。

每个逻辑镜头除了图形，还要有 1 到 3 条留在画面上的短句（`title`、`points` 或 `note`），和口播是同一件事。底部字幕不算。章节名可以用概述、小结，不要用引子、收束、导言。结尾不要重复开场的卡片。

## 声画字说同一件事

- 口播说到哪，画面就指到哪：新元素在对应的词念出时出现（提示点），当前讲的元素高亮。
- 字幕就是口播原文，分块显示；画面上的文字不要和口播打架（画面放关键词，口播说完整句子）。
- 同一时刻只让观众看一个重点：其他元素压暗或保持不动。

## 事实与数字

- **素材里没有的数字不许编。** 用了数字就写明出处（BigNumber / BarChart 的 `source` 必填）；没有出处就改成定性说法或删掉。
- 引用必须是原话并注明出处。
- 按已有稿落地时，口播逐字来自原稿，不补充原稿没有的信息。
- 算法的步骤、复杂度从 trace 的真实运行结果出发，不凭记忆描述。

## 节奏

- 一句一个意思，12–35 个字；复杂的地方放慢（句子 `rate: "-10%"`、`pauseAfterSec`），过渡的地方可以快。
- 一个镜头讲清一个关系就换；同一画面讲太久（验收会提示超过 `qa.freezeWarnSec` 秒不动）要加入随口播推进的变化。
- 开头 10 秒内抛出问题或结论，不要长篇铺垫。
