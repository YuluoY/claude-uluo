# atomic-component.md 模板

原子组件需求清单——回答"项目需要哪些原子组件"和"有什么特殊要求"。仅列出项目实际需要的原子组件及简短特殊要求，**不写详细 Props/事件/状态/样式 API/测试矩阵**——详细 API 由 ui-component-creator 在实现阶段产出。

> 产出路径：`specs/components/atomic.md`（单文件清单）

## 填写指南

### 清单定位
- 本清单是"需求输入"，不是"实现规范"——不要越界写 API
- 详细 Props/事件/状态由 ui-component-creator 在实现阶段基于真实代码产出
- 越界写 API 会导致需求与实现脱节——spec 阶段写的 API 在编码时往往已经被改了

### 组件名
- 使用项目组件库的标准命名（如 Ant Design 的 `DatePicker`，不要写成 `Datepicker` 或 `日期选择`）
- 同类组件不要重复列——`Input` 和 `TextInput` 选一个

### 用途列
- 一句话说清在项目中用来做什么——"通用按钮操作"比"按钮"有用
- 如果某个组件用途特殊（如 `Button` 在某场景必须支持 loading 态），写到"特殊要求"列

### 特殊要求列
- 只写项目特定的额外要求——组件库默认能力不要写
- 要求要具体可验证——"需支持农历"比"需更好用"有用
- 没有特殊要求填"无"，不要留空

### 复用策略
- 项目通常已引入组件库——优先复用，不要重复造轮子
- 只有组件库确实不满足时才自行封装，并在 plan 中标注

### 大小控制
- 单清单控制在 50-80 行
- 原子组件通常 10-20 个，超过 30 个说明划分粒度可能有问题
