# 影响分析协议（Impact Analysis Protocol）

## 目的

在 L1 spec 阶段，系统化评估变更对已有资产的影响，产出结构化影响清单。

## 扫描三维度

### 文档维度

扫描已有 `spec.md` / `plan.md` / `tasks.md`，定位受影响章节。

- **spec.md**：
  - 哪些功能需求（FR-x）受影响？
  - 哪些用户故事（US-x）受影响？
  - 哪些验收标准受影响？
- **plan.md**：
  - 哪些模块设计受影响？
  - 哪些 API 契约受影响？
  - 哪些测试策略受影响？
- **tasks.md**：
  - 哪些任务需要重新执行？
  - 哪些任务需要新增？

### 代码维度

根据 spec 的影响范围章节定位代码文件。

- 哪些文件需要修改？
- 哪些文件需要新增？
- 哪些文件需要删除？

> 不精确到行号（那是 L3 tasks 的事），只精确到文件/模块级。

### 设计稿维度

如果存在设计稿，扫描受影响的组件。

- 哪些组件需要修改？
- 哪些组件需要新增？
- 哪些组件需要删除？

## 影响类型

| 类型 | 含义 |
|------|------|
| **新增（ADDED）** | 变更需要创建新的章节/文件/组件 |
| **修改（MODIFIED）** | 变更需要改动已有的章节/文件/组件 |
| **删除（REMOVED）** | 变更需要移除已有的章节/文件/组件 |

## 风险等级评估标准

### 高风险

- 影响核心功能
- 跨模块改动
- 涉及数据迁移
- 破坏现有 API 契约

### 中风险

- 单模块内功能调整
- 新增非核心功能
- 修改内部实现但不改 API

### 低风险

- 单字段修改
- 样式调整
- 文案修改
- 配置参数调整

## 影响清单输出格式

```markdown
## 影响范围

### 文档影响
| 文档 | 章节 | 影响类型 | 风险等级 | 说明 |
|------|------|---------|---------|------|
| spec.md | ## 功能需求 > FR-1 | MODIFIED | 中 | 需要修改触发条件 |
| spec.md | ## 功能需求 > FR-3 | ADDED | 低 | 新增叠加规则 |

### 代码影响
| 模块 | 文件 | 影响类型 | 风险等级 | 说明 |
|------|------|---------|---------|------|
| coupon-service | service/ | MODIFIED | 高 | 叠加逻辑影响核心计算 |

### 设计稿影响
| 组件 | 影响类型 | 风险等级 | 说明 |
|------|---------|---------|------|
| CouponList | MODIFIED | 中 | 需要显示叠加信息 |
```

## 扫描流程

1. **Step 1**：解析变更需求，提取关键词
2. **Step 2**：在 `spec.md` 中搜索关键词，定位受影响章节
3. **Step 3**：根据 spec 的影响范围章节，定位代码模块
4. **Step 4**：如果有设计稿，扫描组件清单
5. **Step 5**：评估每个受影响项的风险等级
6. **Step 6**：产出结构化影响清单
