# 调研报告模板

调研报告是 spec 的信息基础——记录多渠道调研的完整过程、多方案对比、信息来源。spec 从中提炼结论。

> 本文件是 [research-protocol.md](../references/research-protocol.md) 的产出模板，[spec-template.md](./spec-template.md) 的前置输入。

## 填写指南

### 调研目标
- 从需求中倒推：要实现这个功能，我们需要知道什么？
- 问题要具体——"怎么做"比"调研一下"好

### 知识缺口与结论
- 这是调研报告最核心的表格——所有缺口都应该在这里闭合
- "可信度"不是装饰：官方文档是高，个人博客一句话是低
- 如果某个缺口没有找到满意答案，标注"待确认"并列入综合建议的"待确认项"

### 业界方案对比
- 每个维度一个对比表——不要把所有方案塞进一个表
- "本项目适用性"是最重要的列——不是业界最好的方案就是最适合的
- 被排除的方案也要记录——这是"为什么不选"的决策依据

### 综合建议
- 推荐方案必须有调研结论作为支撑，不能凭空推荐
- "待确认项"诚实列出——承认不确定比假装确定好

### 与 spec 的关系
- 调研报告是"过程文档"——记录探索过程、多方案对比、死胡同
- spec 是"结论文档"——从调研报告中提炼关键结论，去掉探索过程
- spec 的"调研依据"章节是调研报告的摘要，不是重复

### 大小控制
- 小功能：调研报告控制在 100 行以内，知识缺口 3-5 个
- 大功能：可以更详细，但每个方案对比不超过 10 行
