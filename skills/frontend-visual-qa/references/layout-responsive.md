## 一、信息层级设计

### 核心原则

先用结构建立层级——布局、分组、字体、间距、对齐优先于颜色效果。每一个 section 出现在页面上必须有一个信息架构上的理由：用户在这里需要完成什么任务？

- SaaS、中后台、CRM、dashboard、内部工具优先清晰、可扫描、高效率、导航可预测。
- 工具型产品不要默认生成 landing page hero。
- 不要卡片套卡片，也不要把 card 当成所有区块的默认答案。

### 视口分区模型

看到一个页面先分区，再决定每个区放什么：

```
视口
├── 导航区（顶栏 64-80px / 侧栏 200-280px）— 固定，不参与内容滚动
├── 内容区（剩余空间）
│   ├── 主工作面 — 表格 / 表单 / 详情 / 编辑器 / 图表
│   └── 辅助区 — 筛选 / 操作栏 / 摘要 / 面包屑
└── 上下文区（可选） — 右侧面板 / 底部状态栏 / 侧边信息
```

关键：**先分配空间，再填内容。** AI 的默认流程是"有内容 → 放进 div → 堆成列 → 溢出就滚动"——把它翻转成"有多少空间 → 这个空间的任务是什么 → 什么内容必须出现在这个空间里"。

### 每个 Section 必须回答

写完一个 section 后，这个 section 应当能回答：**"用户在这一段要做什么？"**
- 不能回答 → 这个 section 没有存在的理由，删除或合并
- 两个 section 回答同一件事 → 合并
- 回答"让页面更好看" → 不是理由，删掉或换成承担功能的内容

## 二、视口空间设计

### 默认：视口内优先

AI 的最大布局盲区是把所有内容堆成一个可滚动的垂直列。正确的默认方向是反过来的：

**内容必须优先填充视口。只有当视口确实承载不了内容时，才引入滚动。**

引入滚动之前先问三个问题：
1. 这个内容本身是否就不可能在视口内？（长表格、代码编辑器、消息列表 → 天然需要滚动）
2. 能否用渐进呈现把次要内容移走，让核心内容留在视口内？
3. 如果能留在视口内但需要压缩间距和字号——压缩后的可读性和可操作性是否合格？

### 页面滚动 vs 局部滚动的决策树

```
这个区的内容天然很长？
  ├── 是（表格/日志/编辑器/消息列表/无限列表）
  │     → 局部滚动。容器设 max-height，overflow: auto。
  │       页面本身不滚动或最小滚动。
  │       滚动容器必须有清晰边界和 sticky header。
  │
  └── 否（详情/设置/仪表盘/工具页）
        → 默认让内容 fit 视口。如果不行：
          1. 先做渐进呈现——把低频内容移出主屏
          2. 再考虑局部滚动（侧栏固定、内容区滚动）
          3. 最后才接受页面级滚动
```

### AI 五种视口反模式

| 反模式 | 判定 | 修复 |
|--------|------|------|
| 整页滚动 | 所有内容堆成垂直列，一个 section 接一个，页面无限滚动 | 先判断：每个 section 是否必须在视口外？不是就放视口内 |
| 一屏塞太多 | 不确定优先级就把所有信息堆在主屏，导致拥挤和认知过载 | 只放用户 95% 时间需要的；其余渐进呈现 |
| 没用的留白 | 内容挤在中间，四周是大片空白——空白存在但没有结构目的 | 空白必须服务分组：组内紧、组间松。如果空白不分组内容，收紧它 |
| 布局无意图 | 所有 section 都是"标题+内容+CTA"，看不出任何功能顺序 | 每个 section 必须有一个功能理由。如果不能回答"用户在这段做什么"，删掉 |
| 导航吃掉内容 | 大 nav + 面包屑 + 标题栏 + tabs 叠加吃掉 30-40% 视口，剩余工作面过小 | Nav ≤ 80px，面包屑和标题如果同时存在考虑合并。内容区必须 > 60% 视口高度 |

### 布局硬数字

- **Nav 桌面一行，高度 ≤ 80px**。两行 nav = 设计破损。
- **同一布局家族每页最多一次**。8 个 section 的页面至少 4 种不同布局。
- **zigzag image+text split 连续最多 2 段**。第 3 段换布局。
- **Mobile collapse 必须显式声明**：每段多列布局在组件内写清楚 `< 768px` 降级行为。
- **用 `min-h-[100dvh]`，严禁 `h-screen`**。iOS Safari 地址栏抖动。
- **flex/grid item 必须设 `min-width: 0`**，防止内容撑破容器。
- **`overflow: hidden` 不能设在有 dropdown/modal/tooltip 的父容器上**。

## 三、间距空间系统

### 间距不是"元素间的空隙"——间距是层级

AI 的默认是给所有 gap/margin 设同一个值（通常是 16px 或 24px）。这导致所有内容看起来是同一层级——用户无法靠空间位置判断内容之间的关系。

正确的间距有三个层次，**每层的值差 2-4 倍**，间距的大小变化本身传递信息：

| 层级 | 范围 | 用途 | 语义 |
|------|------|------|------|
| Section | 64-128px | 大区块之间 | "新话题开始了" |
| Component | 24-48px | 卡片/面板/组件之间 | "这些是在一起的内容" |
| Element | 8-16px | 组件内部（label-input、按钮之间、列表项） | "这些是一个整体" |

### 空间组织内容——不是"剩下的地方"

```
组内紧（亲和性） → 8-16px  — 告诉用户这些东西是一个整体
组间松（分离性） → 48-128px — 告诉用户这些东西是不同的

一个间距能回答"这两个东西是什么关系"：
  - 紧密关联？→ element 间距
  - 同组但独立？→ component 间距
  - 不同话题？→ section 间距
```

### 基于 4px/8px 的 spacing scale

```
8    — 最小单元间距（icon-text、label-input）
16   — 默认元素间距（按钮之间、表单项之间）
24   — 组件内部边距（card padding、panel padding）
32   — 组件间小间距
48   — 组件间默认间距
64   — section 小间距
96   — section 默认间距
128  — section 大间距（英雄区、大信息分区）
```

**不是"选一个 8 的倍数就对"——选哪个值取决于这两个东西之间的关系紧密度。**

## 四、Hero 纪律

Hero 是 AI 前端产出的最高频灾区。以下为 MUST 级硬约束：

- **最大 4 个文本元素**：eyebrow/brand-strip（可选，最多一个） + headline + subtext + CTAs（1 主 + 最多 1 次）。
- **Hero 内禁止放置**：trust micro-strip、tagline below CTAs、feature bullet list、social-proof avatar row、pricing teaser。
- **"Trusted by / Used by" logo wall 必须在 Hero 下方**作为独立 section，严禁挤进 Hero flex 行。
- **Hero top padding ≤ pt-24**（桌面）。更大的 padding 让内容浮在视口半空，读起来像布局 bug。
- **Hero 必须 fit 初始视口**：headline ≤ 2 行，subtext ≤ 20 单词且 ≤ 4 行，CTA 可见不滚动。
- **Hero 需要真实视觉**：文字 + gradient blob 不是 hero，是占位符。
- **禁止 Hero 内出现**：version 标签（V0.6/BETA/INVITE-ONLY）、locale/天气 strip、scroll cues、decoration text strip。

## 五、路由内容区

- 禁止机械重复"路由标题 + 描述"。
- 标题只有在提供真实上下文时才出现，例如对象详情、编辑流程、向导步骤或无导航独立页。
- 路由内容区应优先展示真实工作面：表格、表单、详情、图表、编辑器、时间线、设置项或流程控件。

## 六、渐进呈现策略

> 核心参考：NN/G Progressive Disclosure。本模块基于 NN/G 适用性研究转化为 AI 可执行的判断规则。

### 原则

**默认先判断"这一屏要让用户完成什么"，然后只放那个任务的内容。其余全部渐进呈现。**

### 分层式（Progressive Disclosure）— 默认策略

核心功能在主屏上，次要功能藏在触发后面。大多数用户从不进入次级层。

什么时候用：
- 主屏 = 用户 95% 时间需要的东西
- 次级 = 偶尔需要的低频/高级/辅助功能
- 次级入口必须有清晰标签，让用户猜到里面有什么（strong information scent）

什么时候**不**能用：
- 不该隐藏的藏了 → 用户每次操作都要额外点击
- 不该显示的塞进主屏了 → 主屏拥挤、认知过载
- 超过 2 层深度 → 用户迷路（>2 层 = 信息架构有问题，先整理 IA）

### 分步式（Staged Disclosure）— 表单/流程专用

线性步骤，每步只展示当前需要的。用户逐步推进。

什么时候用：
- 任务可以分解为独立步骤，步骤间不互相依赖
- 每个步骤的目的对用户清晰

什么时候**不能**用：
- 步骤之间用户需要来回跳（酒店选房和看价格不分开——它们是同一决策）
- 步骤过多 → 用户被"过度导航"拖慢

### 常见渐进呈现控件及其适用场景

| 控件 | 适用 | 不适用 |
|------|------|--------|
| 折叠面板 (Accordion) | 低频设置、说明文案、可选字段、高级筛选 | 关键主任务——不能藏在里面 |
| 标签页 (Tabs) | 同一对象不同视角（概览/配置/权限/日志） | 步骤流程——tab 没有先后顺序 |
| 抽屉 (Drawer) | 不中断主列表上下文的详情、编辑、筛选 | 承载复杂长表单 |
| 对话框 (Modal) | 短流程确认、创建、危险操作、少量字段编辑 | 复杂多步编辑——modal 隐藏了用户需要的上下文 |
| Popover | 轻量补充信息、快捷操作、局部选择 | 主要工作界面——太小 |

### 判定规则

做渐进呈现决策时只用一条规则：**"用户 95% 的时间需要这个信息/操作吗？"**
- 是 → 放主屏
- 否 → 放到次级入口，但入口标签必须让用户猜到里面是什么
- 一层入口搞不定 → 先重新整理信息架构，不是再加一层

## 七、响应式实现

### WCAG 2.2 1.4.10 Reflow（MUST）

内容在 320px CSS 宽度下必须可用，**不出现横向滚动**。例外只有表格、地图、图片等天然需要二维布局的内容——即便如此也必须提供替代方案（横向滚动表格、堆叠行、summary 卡片）。

### 移动优先

- 基础样式 = 移动端。min-width media query 只在需要加复杂度时才用。
- 不基于设备尺寸设断点——让内容定义断点。
- 断点参考：768px（tablet nav 展开）、1024px（侧栏出现）、1280px（内容区上限）。

### 流体布局

```css
/* Grid 自动响应——不需要 media query */
.grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(280px, 1fr)); gap: 1.5rem; }

/* Flexbox 换行——1D 内容流 */
.flex-wrap { display: flex; flex-wrap: wrap; gap: 1rem; }
```

### Container Queries — 组件级响应

组件按自身容器宽度响应，不是整个 viewport。这对 dashboard 组件特别重要——同一个卡片在侧栏打开/关闭时、在宽窄不同列中应自动适配。

```css
.card-wrapper { container-type: inline-size; }
@container (min-width: 400px) { .card { /* 宽版布局 */ } }
```

### 流体排版

`font-size` 用 `clamp()` 给出一个范围——在 320px 手机上不被切断，在 2560px 显示器上不大到离谱。

```
clamp(最小值, 缩放公式, 最大值)
font-size: clamp(1rem, 1.5vw + 0.5rem, 1.25rem);
```

### 触摸目标

- 交互元素 ≥ 44×44px（Apple HIG）/ 48×48px（Material Design）
- 相邻可点击目标间距 ≥ 8px
- 移动端菜单、按钮、表单控件、tab 全部适用

### 图片防 CLS

- 所有 `<img>` 设显式 `width` 和 `height` 属性
- CSS 中设 `max-width: 100%; height: auto;`
- 对于宽高比不固定的容器用 `aspect-ratio`
- LCP 元素设 `fetchpriority="high"`，首屏之外 lazy-load

## 八、视口验收

- 检查窄屏手机（320-480px）、平板（768px）、桌面（1024-1440px）、宽屏（1920px+）。
- 在任何视口下不出现非预期滚动条；宽表格、长内容如有滚动必须是有意设计的。
- 页面级滚动和局部滚动不能互相抢夺；移动端必须能清楚进入、滚动和退出局部内容区。
- 文本不重叠、不裁切、不逃出按钮、卡片、标签页、表格单元格、弹层或侧边栏。
- 表格必须有明确移动端策略：横向滚动、堆叠行、列优先级或替代 summary 卡片。
- Modal、Drawer、Popover、Dropdown 不超出视口且可关闭。
- 触摸目标可用（≥44×44px，间距 ≥8px）。
