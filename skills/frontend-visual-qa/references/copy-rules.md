## 一、通用原则

三 C：**Clear（清楚）、Concise（精炼）、Contextual（符合上下文）**。

- 用户不应需要重读一句话才能理解它。
- 每个词必须挣到自己的位置。删词直到意思改变为止。
- 同一消息在不同用户旅程阶段需要措辞不同——新用户和回头客看到的不一样。

全局守则：
- 现在时主动语态。"消息已发送" 不用 "消息已被发送"。
- 数字用阿拉伯数字——"3 个项目" 不用 "三个项目"。
- 指代界面元素时用其标签——"点击 **保存**" 不用 "点击下方按钮"。
- 不双重否定、不俚语、不文化引用。

## 二、按钮和链接

**按钮标签必须回答一个问题：点了之后会发生什么？**

- ✅ "创建账户"、"发送账单"、"下载报告"——verb + object
- ❌ "确定"、"是"、"下一步"、"提交"、"OK"——没有独立语义
- 数据：ParallelHQ 实测 "Next" → "Create account" 完成率 +14%，"Submit" → "Send invoice" 点击率 +18%

**链接文本脱离上下文仍能理解。**

- ✅ "查看定价方案"、"下载最新报告"
- ❌ "点击这里"、"了解更多"——屏幕阅读器 link-out-of-context 下无意义

**同一意图的 CTA 整页只有一个标签。**

- "Get in touch" + "Contact us" + "Let's talk" → 选一个，全页统一

## 三、错误信息

**三要素模板：①什么问题 ②为什么 ③下一步操作。**

```
✅ "卡号不完整。请输入全部 16 位数字后重试。"
   → 什么：卡号不完整 | 为什么：缺少数字 | 下一步：输入完整后重试

❌ "出错了。"
   → 不知道什么错了、不知道是系统问题还是操作问题、不知道怎么恢复
❌ "Oopsie! Something went sideways 🙁"
   → 错误时幽默激怒用户——这是受阻的时刻，不是轻松的场合
```

- 错误信息对应高亮出错的字段。
- 不只用颜色传达错误——图标 + 文本 + 红色边框。
- 区分可恢复（网络错误→重试）和不可恢复（401→跳登录），文案不同。
- 服务端错误码不暴露给用户——翻译成人类可理解的描述。

## 四、空状态

> 空状态的代码实现（渲染时机、骨架屏 vs Spinner）见 uluo `ui-states.md`。本模块只覆盖空状态的文案策略。

**空状态不是空白——是引导用户完成首次操作的入口。**

空状态 = 引导标题 + 一句话说明 + 行动按钮。

| 类型 | 标题方向 | 说明方向 | 行动 |
|------|---------|---------|------|
| 新建型 | "还没有项目" | "创建第一个项目开始协作" | "新建项目" |
| 搜索型 | "未找到匹配结果" | "试试其他关键词，或清除筛选条件" | "清除筛选" |
| 权限型 | "你没有访问权限" | "联系管理员申请查看权限" | "申请权限" |
| 初始型 | "欢迎！从这里开始" | "完成这三步设置，开始使用" | "开始设置" |

- 空状态标题不责备用户——"暂无内容" 不用 "你没有创建任何内容"。
- 空状态可以配插图——但插图不能是唯一的信息载体。

## 五、表单微文案

**Label：** 简短、清晰、名词短语。"邮箱地址" 不用 "请输入您的电子邮箱地址"。

**Placeholder：** 例子而非标签。`example@mail.com` 不用 "请输入邮箱"——label 已经说了是邮箱。placeholder 应展示合法输入格式。

**Helper text：** 需要额外解释时的补充说明。不重复 label 已经说过的内容。"密码需包含至少 8 个字符，包括一个数字和一个大写字母"——这是 helper text 该做的事。

**Tooltip：** 补充说明，不是关键信息。如果信息对完成任务至关重要——放 label 旁边或 helper text 里，不要藏在 tooltip 中。

## 六、确认与反馈

**确认信息：** 告诉用户操作成功了——不是通知"系统收到指令了"。

- ✅ "消息已发送"、"项目已保存"、"3 个文件已删除"
- ❌ "操作成功"、"请求已处理"——没说清楚发生了什么

**加载文案：** 告诉用户正在发生什么——不是只放一个 spinner。

- ✅ "正在加载你的项目..."、"正在生成报告..."
- ❌ 没有任何文字，只有转圈

**Toast：** 自动消失，用于可恢复操作的瞬时反馈。不用于需要用户确认的关键信息——那种用 inline message 或 dialog。

## 七、禁止项

### 假精确数字
`92%`、`4.1×`、`48k`、`5.8 mm`——三个合法来源：真实数据 / 标记为 mock / 品牌真实声明。AI 编造的"看起来像真的" → 禁止。

### 填充动词
elevate、seamless、unleash、next-gen、revolutionize、empower、leverage、transform、supercharge、streamline、world-class、enterprise-grade、cutting-edge、game-changer、mission-critical——用一个描述产品实际做什么的具体动词代替。

### 通用人名和品牌名
John Doe、Sarah Chan、Jack Su、Acme、Nexus、SmartFlow、Cloudly → 用贴近行业语境的真实感名称。

### em-dash
`—` 在标题、eyebrow、标签、引文、图片说明中作为"设计气息"装饰 → 禁止。正文停顿用逗号、句号、冒号或括号。

## 八、AI 特有文案反模式

| 反模式 | 例子 | 修复 |
|--------|------|------|
| 过度解释 | "点击下方按钮以完成订单提交流程" | "提交订单" |
| 幽默在错误时 | "哎呀！好像出了点小问题 🤷" | "订单提交失败，请检查收货地址后重试" |
| 技术术语暴露 | "user_id 不能为空" | "请选择一位用户" |
| 长度不匹配 | 英文 "Save" → 中文 "保存草稿并继续编辑"（3→7 字，按钮撑爆） | 设计按钮文案时用最长语言测试 |
| 无上下文的泛化 | 所有错误信息都用"操作失败" | 每个错误消息命名出错的操作和原因 |

## 九、自检清单

- [ ] 所有按钮标签是 verb + object？
- [ ] 链接文本脱离上下文仍能理解？
- [ ] 每个错误信息包含 ①什么问题 ②为什么 ③下一步？
- [ ] 空状态有引导标题 + 说明 + 行动按钮？
- [ ] placeholder 是例子而非标签？
- [ ] 确认信息说清楚了什么操作成功了（而非"操作成功"）？
- [ ] 检查了假精确数字——每个数字有真实来源？
- [ ] 检查了填充动词——替换为具体描述？
- [ ] 检查了通用人名/品牌名——替换为真实感名称？
- [ ] 没有 em-dash 作为设计装饰？
- [ ] 同一页面没有重复的 CTA 意图？
- [ ] 错误、加载、空状态文案没有"通用泛化"——每条都命名了具体操作？
