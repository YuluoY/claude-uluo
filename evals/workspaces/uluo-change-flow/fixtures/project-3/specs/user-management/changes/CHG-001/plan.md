# 用户管理模块新增角色权限系统（RBAC）变更 Plan

> 日期: 2026-06-25 | 作者: huyongle | 关联变更 spec: ./spec.md

## 技术方案选择

### 方案对比

| 方案 | 优点 | 缺点 | 复杂度 |
|------|------|------|--------|
| 方案 A：RBAC（基于角色的访问控制） | 模型成熟稳定；角色-权限多对多解耦；管理界面友好；社区资料丰富 | 角色爆炸问题（可通过角色继承缓解）；细粒度不如 ABAC | 中 |
| 方案 B：ABAC（基于属性的访问控制） | 细粒度极高；策略灵活；适合复杂动态场景 | 实现复杂度高；策略学习曲线陡；过度设计风险 | 高 |
| 方案 C：ACL（访问控制列表） | 实现简单；直接绑定资源与用户 | 难以批量管理；用户量大时维护成本高；无角色抽象 | 低 |

### 选择结论

- **选择**: 方案 A（RBAC）
- **理由**: 业务需求明确按角色区分权限（超管/管理员/只读），RBAC 模型与需求匹配度最高。角色-权限多对多模型支持后续扩展，复杂度适中。ABAC 对当前场景过度设计，ACL 在用户量增长后维护成本不可控。

- **改为**: 在 US-3 之后新增 US-4（管理员创建角色）、US-5（管理员分配权限给角色）、US-6（管理员为用户分配角色）

### ADDED: spec.md > ## 功能需求 > FR-4

- **插入位置**: 在 FR-3（删除用户）之后
- **新内容**:
  ```
  ### FR-4: 角色管理
  - **优先级**: P0
  - **触发条件**: 管理员在角色管理页提交角色表单
  - **预期行为**: 创建/编辑/删除角色，角色包含名称和描述
  - **边界条件**: 角色名不能重复；内置角色不可删除
  ```

### ADDED: spec.md > ## 功能需求 > FR-5

- **插入位置**: 在 FR-4 之后
- **新内容**:
  ```
  ### FR-5: 权限管理
  - **优先级**: P0
  - **触发条件**: 管理员在角色编辑页勾选权限项
  - **预期行为**: 为角色分配/撤销权限，权限以"资源:操作"形式定义（如 user:read、user:write）
  - **边界条件**: 权限项为系统预定义，不支持自定义
  ```

### ADDED: spec.md > ## 功能需求 > FR-6

- **插入位置**: 在 FR-5 之后
- **新内容**:
  ```
  ### FR-6: 用户角色分配
  - **优先级**: P1
  - **触发条件**: 管理员在用户编辑页选择角色
  - **预期行为**: 为用户分配一个或多个角色，用户权限取所有角色权限的并集
  - **边界条件**: 一个用户至少分配一个角色；删除用户时同步解绑角色关系
  ```
