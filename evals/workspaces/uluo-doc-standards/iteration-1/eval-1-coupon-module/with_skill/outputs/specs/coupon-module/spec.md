# 优惠券模块 需求规格说明

> 日期: 2026-06-08 | 作者: AI | 状态: 已确认

## 背景与动机

当前项目已有 promotion/ 满减活动模块，支持基于活动条件的满减优惠，但缺乏面向用户的优惠券体系。用户无法获得个性化优惠券并在下单时自主选择，运营人员也缺少灵活发放营销券的工具。

引入优惠券模块后，管理员可以创建两种类型的优惠券活动——满减券（固定金额减免）和折扣券（百分比折扣），设置有效期和使用条件。用户下单时可以选用一张优惠券，系统在并发场景下保证库存扣减的正确性（不超发）。

| US-3 | 管理员 | 作为管理员，我希望手动终止或延期优惠券活动，以便根据运营需要灵活调整 | FR-3, AC-4 |
| US-4 | 普通用户 | 作为用户，我希望查看可用优惠券列表，以便在下单时选取最合适的优惠券 | FR-4, AC-5 |

### 目标
- 支持管理员创建、查看、管理两种类型优惠券活动
- 支持用户浏览可用优惠券并在下单时选用一张
- 并发场景下库存扣减正确，不超发
- 与现有 promotion/ 满减模块可叠加计算（当都满足时）

### 非目标（明确不做的事）
- 不构建优惠券分发/推送系统（用户自行领取或后台发放，本期不在范围内）
- 不支持优惠券批次码/礼品卡功能（本期不做）
- 不支持多张券叠加使用（每订单限用一张）
- 不构建前端 UI（本期仅后端 API）
- 不构建优惠券使用统计分析 Dashboard

## 功能需求

### FR-1: 创建优惠券活动
- **描述**: 管理员创建优惠券活动，需指定活动名称、券类型（满减券/折扣券）、有效期（开始/结束时间）、总发行量、最低消费金额、优惠金额（满减券）或折扣率（折扣券）。
- **优先级**: P0
- **触发条件**: 管理员在后台提交创建表单
- **预期行为**: 系统校验参数（有效期开始 < 结束、金额 > 0、折扣率 0-100），成功创建后返回优惠券活动详情
- **边界条件**: 
  - 满减券的优惠金额必须小于最低消费金额
  - 折扣券的折扣率必须在 1-99 之间
  - 折扣券可设优惠上限金额（如"最多减 50 元"），不设则为 0 表示无上限

### FR-2: 查看优惠券活动列表
- **描述**: 管理员可以分页查看所有优惠券活动，支持按状态（未开始/进行中/已结束/已终止）筛选
- **优先级**: P0
- **触发条件**: 管理员访问优惠券活动列表页
- **预期行为**: 返回分页列表，包含活动基本信息、已领/已用数量、状态
- **边界条件**: 无筛选条件时返回全部，按创建时间倒序

### FR-3: 管理优惠券活动状态
- **描述**: 管理员可以手动终止进行中的活动（状态变为已终止），或延后已设置结束时间的活动
- **优先级**: P1
- **触发条件**: 管理员在详情页执行操作
- **预期行为**: 状态变更即时生效，已终止的活动用户端不再可见，已领取的券不受影响
- **边界条件**: 已结束/已终止的活动不可再修改状态

### FR-4: 用户查看可用优惠券
- **描述**: 用户查看自己持有的、在有效期内的、尚未使用的优惠券
- **优先级**: P0
- **触发条件**: 用户进入下单页或优惠券中心
- **预期行为**: 返回用户持有的可用券列表，包含券信息和使用条件
- **边界条件**: 库存已用完的券不显示；已过期、已使用的不显示

### FR-5: 下单选用优惠券
- **描述**: 用户在下单时从可用优惠券中选择一张，系统校验条件（最低消费、有效期、库存），计算优惠后金额
- **优先级**: P0
- **触发条件**: 用户提交订单时携带优惠券 ID
- **预期行为**: 
  1. 校验优惠券有效性（存在、在有效期、用户持有、未使用）
  2. 校验使用条件（订单金额 >= 最低消费金额）
  3. 计算优惠金额（满减券直接减、折扣券按比例减）
  4. 原子扣减库存（used_quantity + 1，不超过 total_quantity）
  5. 记录订单-优惠券关联
- **边界条件**: 
  - 优惠券不满足条件时返回具体错误码（过期、金额不足、库存不足等）
  - 并发场景下同一张券被多个订单同时使用时，只有一个成功
  - 如果订单回滚，已扣减的优惠券库存需回滚

## 非功能性需求

### 性能
- 用券校验+扣减 P99 < 200ms（含数据库悲观锁等待）
- 优惠券列表查询 P99 < 300ms（分页 20 条）
- 支持并发领券/用券 QPS ≥ 100（单实例）

### 安全
- 管理端接口（创建/管理优惠券）需管理员权限认证
- 用户只能用自己持有的券，不能越权使用他人券
- 券码不可被枚举/猜测（8 位随机字母数字，共 36^8 组合空间）

### 可维护性
- 优惠券状态变更记录操作日志（操作人、时间、操作类型）
- 关键业务操作（创建优惠券、用户用券）记录 INFO 级别日志，异常记录 ERROR 级别
- 优惠券相关配置（默认过期天数、最大折扣率等）通过配置文件管理

## 依赖与前置条件

- 项目已有用户认证体系（需确认如何获取当前登录用户和管理员角色）
- 项目使用 MySQL InnoDB（支持行级锁和事务）
- 项目已有 promotion/ 模块提供代码风格参考（锚点模块）
- MyBatis Mapper 扫描配置正常

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 悲观锁导致数据库连接池耗尽 | 低 | 高 | 严格控制事务范围（仅扣库存时加锁），设置合理连接池大小和超时时间 |
| 优惠券和满减活动叠加计算逻辑冲突 | 中 | 中 | 明确叠加规则（先满减再优惠券？还是反过来？），写在 spec 中并增加单元测试覆盖 |
| 用户领券接口被恶意刷量 | 中 | 中 | 管理端创建+用户领取模式改为管理端发放，本期暂不开放用户自助领取 |
| 数据库时区导致优惠券提前/延迟过期 | 低 | 中 | 统一使用 UTC 存储，API 返回时转为用户时区 |

## 验收标准

- [ ] AC-1: 管理员可以成功创建满减券活动（POST /api/admin/coupons，type=FIXED），返回 200 并包含完整信息
- [ ] AC-2: 管理员可以成功创建折扣券活动（POST /api/admin/coupons，type=PERCENTAGE），返回 200 并包含完整信息
- [ ] AC-3: 管理员可以分页查看优惠券列表（GET /api/admin/coupons），支持按状态筛选
- [ ] AC-4: 管理员可以终止一个进行中的活动（PUT /api/admin/coupons/{id}/terminate），状态变更即时生效
- [ ] AC-5: 用户可以查看自己持有的可用优惠券（GET /api/coupons/available）
- [ ] AC-6: 用户下单时选用优惠券成功（订单金额 100，满减券满 80 减 10，实际支付 90）
- [ ] AC-7: 用户下单时选用折扣券成功（订单金额 100，8 折券，实际支付 80）
- [ ] AC-8: 并发测试：100 个线程同时对库存为 1 的优惠券执行用券操作，最终只有 1 个成功，99 个收到"库存不足"错误
- [ ] AC-9: 不满足最低消费时用券返回明确错误码 COUPON_MIN_AMOUNT_NOT_MET
- [ ] AC-10: 优惠券已过期时用券返回错误码 COUPON_EXPIRED
- [ ] AC-11: 优惠券已使用时用券返回错误码 COUPON_ALREADY_USED
- [ ] AC-12: 折扣券计算结果精确到分（小数点后两位），向上取整保证商家利益
