# 优惠券模块需求分析文档

## 1. 概述

为电商平台增加优惠券模块，支持管理员后台创建优惠券活动，用户下单时选用优惠券抵扣。需支持两种核心券类型，并保证高并发场景下库存扣减的正确性。

## 2. 功能需求

### 2.1 优惠券类型

| 类型 | 说明 | 关键参数 |
|------|------|----------|
| 满减券 (FULL_REDUCTION) | 订单金额达到门槛后减免固定金额 | 最低消费金额、优惠金额 |
| 折扣券 (DISCOUNT) | 订单金额达到门槛后按折扣率打折 | 最低消费金额、折扣率（如 0.85 表示 85 折） |

### 2.2 管理员功能

**F2.2.1 创建优惠券活动**
- 设置活动名称、描述
- 选择券类型（满减/折扣）
- 设置有效期（开始时间、结束时间）
- 设置使用条件：最低消费金额（如 "满100元可用"）
- 满减券：设置优惠金额（如 "减20元"）
- 折扣券：设置折扣率（如 "8.5折"，存储为 0.85）
- 设置发行总量（库存）
- 设置每人限领数量
- 可选：设置适用商品分类或指定商品

**F2.2.2 管理优惠券活动**
- 查询活动列表（支持按状态筛选：未开始、进行中、已结束）
- 查看活动详情
- 修改活动（仅限未开始的活动）
- 终止活动（提前结束进行中的活动）
- 查看活动统计数据（领取量、使用量）

### 2.3 用户功能

**F2.3.1 领取优惠券**
- 从活动列表中选择可领取的优惠券
- 系统校验：活动状态、库存、用户限领次数
- 领取成功后写入用户优惠券记录

**F2.3.2 查看我的优惠券**
- 查看已领取的优惠券列表
- 按状态筛选：未使用、已使用、已过期
- 查看每张券的详细信息（面值、有效期、使用条件）

**F2.3.3 下单选用优惠券**
- 在结算时展示可用优惠券列表（系统自动过滤不符合条件的券）
- 用户选择一张优惠券
- 系统校验：券是否属于当前用户、是否在有效期内、订单金额是否满足最低消费、券是否未使用
- 计算优惠后金额
- 提交订单时锁定该券

### 2.4 系统功能

**F2.4.1 优惠计算**
- 满减券：`实付金额 = 订单原价 - 优惠金额`（结果不为负）
- 折扣券：`实付金额 = 订单原价 * 折扣率`（保留两位小数，向上取整）

**F2.4.2 库存扣减**
- 领取时扣减活动库存
- 使用优惠券时不需要再次扣活动库存（领取时已扣）
- 支持用户退券（退还活动库存）
- 高并发下保证库存不超发

**F2.4.3 过期处理**
- 定时任务扫描已过期但未使用的优惠券，标记为过期状态
- 过期券退还会占用用户的可领取额度

## 3. 非功能需求

### 3.1 并发安全
- 库存扣减必须使用数据库行级锁（`SELECT ... FOR UPDATE`）或乐观锁（版本号）
- 同一用户同一活动不得重复领取超过限制
- 同一张优惠券不得被重复使用

### 3.2 性能
- 优惠券列表查询支持分页
- 可用优惠券查询响应时间 < 200ms
- 库存扣减操作支持 1000 QPS

### 3.3 数据一致性
- 优惠券状态变更必须在事务内完成
- 订单回滚时需同步回滚优惠券状态

## 4. 状态流转

### 4.1 优惠券活动状态

```
未开始(NOT_STARTED) --> 进行中(ACTIVE) --> 已结束(ENDED)
                     进行中(ACTIVE) --> 已终止(TERMINATED)
```

### 4.2 用户优惠券状态

```
未使用(UNUSED) --> 已使用(USED)
未使用(UNUSED) --> 已过期(EXPIRED)
未使用(UNUSED) --> 已退回(REFUNDED)
```

## 5. 约束与边界条件

- 优惠金额不得超过最低消费金额
- 折扣率范围：0 < 折扣率 < 1
- 优惠后金额最低为 0.01 元
- 一张订单只能使用一张优惠券
- 优惠券不可与其他特定促销活动叠加（预留规则引擎扩展点）
- 发行总量必须大于 0
