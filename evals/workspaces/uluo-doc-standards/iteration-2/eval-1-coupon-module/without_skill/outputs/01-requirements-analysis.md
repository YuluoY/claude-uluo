# 优惠券模块需求分析文档

## 1. 概述

为电商平台构建优惠券模块，支持管理员后台创建和管理优惠券活动，用户在前端领取优惠券并在下单时选用以抵扣订单金额。本模块需支持满减券和折扣券两种核心类型，并确保高并发场景下库存扣减的正确性与数据一致性。

### 1.1 业务背景

电商平台营销体系中，优惠券是最基础且最重要的促销工具之一。通过发放优惠券，平台能够：
- 刺激用户消费，提升客单价
- 吸引新用户首次下单
- 促进特定品类/商品的销售
- 在大促活动中提升转化率

### 1.2 技术约束

- 后端框架：Spring Boot 2.x / 3.x
- 持久层：MyBatis + MySQL 8.0
- API 风格：RESTful JSON
- 并发控制：基于数据库机制的乐观锁
- 事务管理：Spring 声明式事务

## 2. 功能需求

### 2.1 优惠券类型定义

| 类型 | 标识 | 说明 | 计算规则 |
|------|------|------|----------|
| 满减券 | FULL_REDUCTION | 订单金额达到指定门槛后，减免固定金额 | 实付 = max(订单原价 - 优惠金额, 0.01) |
| 折扣券 | DISCOUNT | 订单金额达到指定门槛后，按折扣率打折 | 实付 = max(订单原价 * 折扣率, 0.01) |

**满减券示例**：
- "满100元减20元"：订单金额 >= 100.00，实付 = 订单金额 - 20.00
- "满200元减50元"：订单金额 >= 200.00，实付 = 订单金额 - 50.00

**折扣券示例**：
- "满50元享8.5折"：订单金额 >= 50.00，实付 = 订单金额 * 0.85
- "满200元享9折"：订单金额 >= 200.00，实付 = 订单金额 * 0.90

### 2.2 管理员功能

#### F1: 创建优惠券活动

管理员可创建新的优惠券活动，需配置以下信息：

| 配置项 | 说明 | 校验规则 |
|--------|------|----------|
| 活动名称 | 用于后台管理识别 | 必填，最长100字符 |
| 活动描述 | 补充说明信息 | 最长500字符 |
| 券类型 | 满减券/折扣券 | 必选 |
| 发行总量 | 计划发放的券总数 | 必填，整数 > 0 |
| 每人限领 | 单个用户最多领取张数 | 默认1张 |
| 最低消费 | 使用优惠券的订单金额门槛 | 必填，金额 > 0 |
| 优惠金额 | 满减券的优惠额 | 满减券必填，须 < 最低消费 |
| 折扣率 | 折扣券的折扣率 | 折扣券必填，0 < 值 < 1 |
| 生效时间 | 活动开始时间 | 必填 |
| 失效时间 | 活动结束时间 | 必填，须晚于生效时间 |

#### F2: 管理优惠券活动

- **活动列表查询**：支持按活动名称模糊搜索、按券类型筛选、按活动状态筛选（未开始/进行中/已结束/已终止），支持分页
- **活动详情查看**：包含基本信息、库存情况、领取/使用统计数据
- **修改活动**：仅允许修改"未开始"状态的活动，进行中或已结束的活动不可编辑
- **终止活动**：提前终止进行中的活动。已领取的优惠券在有效期内仍可使用，但用户不能再领取新券

### 2.3 用户功能

#### F3: 领取优惠券

- 用户可在活动列表页面浏览可用活动
- 点击领取按钮发起领取请求
- 系统需校验：活动是否进行中、库存是否充足、用户是否超过每人限领次数
- 领取成功后，生成用户专属优惠券记录

#### F4: 查看我的优惠券

- 展示已领取的所有优惠券列表
- 支持按状态筛选：未使用、已使用、已过期、已退回
- 展示关键信息：券类型、面值/折扣率、使用门槛、有效期
- 支持分页

#### F5: 下单选用优惠券

- 结算页面展示可用优惠券列表，按优惠力度从大到小排序
- 系统自动过滤：已过期、已使用、不满足订单金额门槛的券
- 用户选择一张优惠券后，实时显示优惠后金额
- 提供"优惠预览/试算"接口，无需实际锁定券即可查看优惠结果

### 2.4 系统功能

#### F6: 优惠金额计算

- **满减券计算**：`finalAmount = max(orderAmount - discountAmount, 0.01)`
- **折扣券计算**：`finalAmount = max(orderAmount * discountRate, 0.01)`
- 计算结果采用 BigDecimal，保留两位小数，四舍五入
- 最终金额最低为 0.01 元（防止零金额订单）

#### F7: 库存管理

- 领取优惠券时扣减活动剩余库存
- 用户退回优惠券时恢复活动库存
- 拒绝超发：通过数据库条件 UPDATE 确保 remaining_stock > 0
- 并发场景使用乐观锁（版本号）保证正确性

#### F8: 过期处理

- 定时任务扫描已过期但状态为"未使用"的优惠券
- 将过期券标记为 EXPIRED 状态
- 过期券不计入用户可领取额度（已释放领取资格）

## 3. 状态流转

### 3.1 优惠券活动状态

```
                    ┌──────────────┐
                    │  NOT_STARTED │
                    │  (未开始)     │
                    └──────┬───────┘
                           │ 到达生效时间
                           ▼
                    ┌──────────────┐     管理员手动终止   ┌──────────────┐
                    │    ACTIVE    │ ─────────────────→  │  TERMINATED  │
                    │  (进行中)     │                     │  (已终止)     │
                    └──────┬───────┘                     └──────────────┘
                           │ 到达失效时间
                           ▼
                    ┌──────────────┐
                    │    ENDED     │
                    │  (已结束)     │
                    └──────────────┘
```

- NOT_STARTED：活动已创建但未到生效时间，此时用户不可见不可领
- ACTIVE：活动进行中，用户可领取
- ENDED：活动正常到期
- TERMINATED：管理员手动提前终止

### 3.2 用户优惠券状态

```
                    ┌──────────────┐
                    │    UNUSED    │
                    │  (未使用)     │
                    └───┬────┬─────┘
                        │    │
              ┌─────────┘    └─────────┐
              ▼ 下单使用                ▼ 过了有效期
    ┌──────────────┐           ┌──────────────┐
    │     USED     │           │   EXPIRED    │
    │  (已使用)     │           │  (已过期)     │
    └──────┬───────┘           └──────────────┘
           │ 订单退款退券
           ▼
    ┌──────────────┐
    │   REFUNDED   │
    │  (已退回)     │
    │              │
    └──────────────┘
```

- UNUSED：初始状态，用户已领取但尚未使用
- USED：用户已在下单时使用该券
- EXPIRED：超过有效期且未被使用
- REFUNDED：订单退款后券退回给用户（从 USED 流转而来，不可再次使用）

## 4. 非功能需求

### 4.1 并发安全

| 场景 | 风险 | 解决方案 |
|------|------|----------|
| 多用户同时领取同一活动 | 库存超发 | 乐观锁（版本号）+ 数据库 WHERE 条件 |
| 同一用户并发多次领取 | 超过限领次数 | 数据库唯一索引 uk_user_activity_ordinal |
| 同一优惠券被多次使用 | 重复使用 | 乐观锁（版本号 + status 条件） |
| 订单创建与优惠券锁定不一致 | 数据不一致 | 同一事务内完成 |

库存扣减必须使用带条件的 UPDATE 语句，在数据库层面保证原子性。Service 层实现有限次数重试机制（最多3次，间隔递增）处理乐观锁冲突。

### 4.2 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 可用优惠券查询延迟 | < 200ms | 结算页已过滤排序的券列表 |
| 库存扣减吞吐 | >= 1000 QPS | 单活动领取场景 |
| 活动列表查询延迟 | < 500ms | 管理后台分页查询 |
| 过期处理效率 | 500条/批 | 定时任务分批处理 |

### 4.3 数据一致性

- 优惠券状态变更必须在数据库事务内完成
- 订单创建失败时，已锁定的优惠券必须回退状态
- 订单退款时，优惠券状态同步回退
- user_coupon 表冗余活动关键字段（min_order_amount、discount_amount、discount_rate），作为快照防止活动修改导致历史券的规则变更

### 4.4 可用性

- 定时任务失败不影响主流程（领取和使用接口独立运行）
- 乐观锁重试失败后返回明确错误码，前端可引导用户重试
- 异常情况记录完整日志，便于问题排查

## 5. 约束与边界条件

| 约束项 | 说明 |
|--------|------|
| 优惠金额限制 | 满减券的优惠金额必须严格小于最低消费金额 |
| 折扣率范围 | 折扣券的折扣率须在开区间 (0, 1) 内 |
| 优惠后最低金额 | 实付金额最低为 0.01 元，不为零不为负 |
| 券使用数量 | 每笔订单最多使用一张优惠券 |
| 促销叠加 | 当前版本不支持优惠券与其它促销活动叠加，预留 PromotionRuleEngine 接口 |
| 活动库存 | 发行总量须大于 0，不可为负数 |
| 修改限制 | 进行中和已结束的活动不可修改配置 |
| 不可逆操作 | 活动终止不可恢复；优惠券使用后不可撤销（仅支持退款退券） |

## 6. 验收标准

### 6.1 功能验收

- [ ] 管理员可创建满减券和折扣券活动，参数校验正确
- [ ] 管理员可查询活动列表、查看详情、终止活动
- [ ] 用户可浏览可用活动并领取优惠券
- [ ] 用户可查看已领取的优惠券，按状态筛选
- [ ] 结算页正确过滤并排序可用优惠券
- [ ] 满减券计算：满100减20，订单150元 => 实付130元
- [ ] 折扣券计算：85折，订单150元 => 实付127.50元
- [ ] 过期券自动标记为 EXPIRED

### 6.2 并发验收

- [ ] 库存100张，200个线程并发领取，最终库存为0，最多发放100张券
- [ ] 每人限领1张，同一用户并发领取3次，最终只获得1张券
- [ ] 同一张优惠券并发使用，最终只有一次成功

### 6.3 一致性验收

- [ ] 订单创建事务回滚时，优惠券状态正确回退
- [ ] 订单退款后，优惠券状态正确更新为 REFUNDED
- [ ] 活动修改后，已领取的历史券规则不变
