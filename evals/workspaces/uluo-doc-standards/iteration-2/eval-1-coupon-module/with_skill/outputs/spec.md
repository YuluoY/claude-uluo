# 优惠券模块 需求规格说明

> 日期: 2026-06-08 | 作者: huyongle | 状态: 已确认

## 背景与动机

当前系统已有满减活动模块（promotion/），但缺少灵活的优惠券发放和使用能力。运营需要能够创建独立于满减活动的优惠券活动（满减券和折扣券），用户在订单结算时可选用一张优惠券享受优惠。同时需要保证在高并发下单场景下，优惠券库存扣减不会超卖。

## 用户故事

| 编号 | 角色 | 故事 | 验收线索 |
|------|------|------|---------|
| US-1 | 管理员 | 作为管理员，我希望在后台创建优惠券活动（满减券或折扣券），设置有效期、最低消费金额、优惠金额/折扣率，以便灵活配置营销活动 | FR-1 |
| US-2 | 管理员 | 作为管理员，我希望查看优惠券活动列表，以便了解所有活动的状态和库存 | FR-2 |
| US-3 | 普通用户 | 作为普通用户，我希望在下单时查看可用的优惠券列表并选用一张，以便享受订单优惠 | FR-3, FR-4 |
| US-4 | 系统 | 作为系统，我希望在并发场景下安全扣减优惠券库存，以便保证不超卖 | FR-5, NFR-1 |
| US-5 | 运维人员 | 作为运维人员，我希望有优惠券操作的日志记录，以便追踪问题和审计 | NFR-3 |

### 目标
- 实现满减券（满 X 减 Y）和折扣券（满 X 打 Z 折）两种优惠券类型
- 管理员可创建、查看优惠券活动，设定有效期、最低消费、优惠力度和库存
- 用户下单时可选用一张有效优惠券，系统自动校验并计算优惠后金额
- 并发场景下库存扣减零超卖

### 非目标（明确不做的事）
- 不实现用户自主领券功能（本期由管理员后台发放）
- 不实现优惠券分享/转赠功能
- 不实现多张优惠券叠加使用（一单仅限一张）
- 不实现优惠券退款退还功能（本期不做）
- 不实现优惠券使用统计分析报表

## 功能需求

### FR-1: 创建优惠券活动
- **描述**: 管理员通过后台接口创建优惠券活动，设定券类型、有效期、使用条件和优惠力度
- **优先级**: P0
- **触发条件**: 管理员调用 POST /api/admin/coupons 接口
- **预期行为**: 系统校验参数（有效期合理性、金额非负、折扣率 0<rate<1），创建优惠券活动记录并返回活动详情
- **边界条件**: 折扣率超出 0-1 返回 400；结束时间早于开始时间返回 400；优惠金额为负数返回 400；同一活动库存必须 >0

### FR-2: 查询优惠券活动
- **描述**: 管理员查看所有优惠券活动列表，支持分页和状态筛选
- **优先级**: P1
- **触发条件**: 管理员调用 GET /api/admin/coupons 接口
- **预期行为**: 返回分页的活动列表，包含活动名称、类型、有效期、库存、状态
- **边界条件**: 空列表返回空数组；page < 1 默认第 1 页；pageSize 超过 100 截断为 100

### FR-3: 用户获取可用优惠券
- **描述**: 用户下单时获取当前可用的优惠券列表（在有效期内、有库存、满足最低消费）
- **优先级**: P0
- **触发条件**: 用户调用 GET /api/coupons/available?orderAmount={金额} 接口
- **预期行为**: 返回满足条件的优惠券列表，按优惠力度降序排列（优惠金额大的在前）
- **边界条件**: 无可用优惠券返回空数组；订单金额为 0 时仅返回无最低消费门槛的券；已过期或无库存的券不返回

### FR-4: 下单使用优惠券
- **描述**: 用户在下单时选择一张优惠券，系统计算优惠后金额
- **优先级**: P0
- **触发条件**: 用户在 POST /api/orders 请求体中附带 couponId
- **预期行为**: 校验优惠券有效性（未过期、有库存、满足最低消费），计算优惠后金额，扣减库存，关联优惠券快照到订单
- **边界条件**: 优惠券不存在返回 404；优惠券已过期返回 400 "优惠券已过期"；库存不足返回 409 "优惠券已抢光"；最低消费不满足返回 400 "未达到优惠券使用门槛"；不传 couponId 则按原价下单

### FR-5: 并发库存扣减安全
- **描述**: 多个用户同时使用同一优惠券时，保证库存扣减的原子性和正确性
- **优先级**: P0
- **触发条件**: 并发请求使用同一优惠券下单
- **预期行为**: 使用乐观锁（version 字段）保证库存扣减线程安全；当库存为 0 时后续请求返回 409
- **边界条件**: 乐观锁冲突时最多重试 3 次，3 次均失败返回 409；库存扣减后不允许为负数；事务回滚时库存同时回滚

## 非功能性需求

### 性能
- 可用优惠券查询接口 P99 延迟 < 100ms
- 下单使用优惠券接口 P99 延迟 < 200ms（允许乐观锁重试开销）
- 支持优惠券表 10 万级数据量下的正常查询（通过索引优化）

### 安全
- 管理员接口需管理员角色认证，普通用户无权创建/编辑优惠券
- 优惠券库存操作需记录审计日志（操作人、时间、变更量）
- 用户仅能使用自己订单内的优惠券，不能通过接口直接扣减他人库存

### 可维护性
- 优惠券策略使用策略模式，新增券种只需新增策略类
- 关键操作（创建活动、扣减库存、使用优惠券）打 INFO 级别日志，包含 traceId
- 优惠券活动参数通过 @Validated 注解校验，错误信息对调用方可读

## 依赖与前置条件

- 依赖项目已有的 Spring Boot + MyBatis 技术栈
- 依赖已有的 OrderService 下单流程，需在其 createOrder 方法中织入优惠券处理
- 依赖已有的用户认证体系（管理员角色判断）
- 前置数据准备：需在数据库中创建优惠券相关表

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 乐观锁在极端并发下重试次数过多导致响应超时 | 低 | 中 | 限制重试次数上限为 3 次，超过后快速失败返回 409；热点优惠券可考虑库存预热 |
| 优惠券金额计算浮点精度问题 | 低 | 高 | 统一使用 BigDecimal，金额保留两位小数，使用 HALF_UP 舍入模式 |
| 与现有满减活动叠加计算逻辑复杂 | 中 | 中 | 优惠券和满减活动分步计算，先满减后优惠券，每步独立可测试 |

## 验收标准

- [ ] AC-1: 管理员可成功创建满减券活动（如"满100减20"），返回完整活动信息
- [ ] AC-2: 管理员可成功创建折扣券活动（如"满200打8折"），返回完整活动信息
- [ ] AC-3: 用户查询可用优惠券时，已过期/无库存/最低消费不满足的券不出现在列表中
- [ ] AC-4: 用户使用满减券下单，优惠金额正确扣减，订单记录含优惠券快照
- [ ] AC-5: 用户使用折扣券下单，优惠金额正确（BigDecimal 精度），订单记录含优惠券快照
- [ ] AC-6: 模拟 10 个并发请求使用同一张仅剩 3 张库存的优惠券，最终库存为 0，仅 3 个请求成功，0 超卖
- [ ] AC-7: 不满足最低消费时使用优惠券返回明确错误提示
- [ ] AC-8: 优惠券库存为 0 时使用返回 409 "优惠券已抢光"
- [ ] AC-9: 管理员接口需要管理员角色，普通用户调用返回 403
