# 优惠券模块 需求规格说明

> 日期: 2026-06-25 | 作者: huyongle | 状态: 草稿

## 背景与动机

当前平台营销能力薄弱，仅支持简单的满减活动配置，无法满足精细化运营需求。运营团队反馈：拉新成本高（无新人专属优惠）、复购率低（无折扣券刺激）、客单价提升手段单一（满减券仅支持固定门槛）。

竞品分析显示，同行业 Top 3 平台均已支持满减券、折扣券、新人券三种券类型，且支持精细化发放与核销。本期补齐优惠券模块，预计可提升新用户转化率 15%、复购率 10%。

| US-2 | 运营人员 | 作为运营人员，我希望按条件批量发放优惠券给目标用户群体，以便精准触达高价值用户 | FR-2 |

| US-4 | 普通用户 | 作为普通用户，我希望下单时系统自动计算最优优惠并核销优惠券，以便获得最大实惠 | FR-4 |
| US-5 | 系统管理员 | 作为系统管理员，我希望系统自动处理过期优惠券的失效与清理，以便避免无效券占用库存 | FR-5 |

### 目标

- 支持满减券、折扣券、新人券三种券类型的创建、发放、核销、过期全生命周期管理
- 领券接口 P99 延迟 ≤ 100ms，核销接口 P99 延迟 ≤ 150ms
- 防止优惠券超发（零超发容忍）
- 与现有订单系统无缝集成，下单自动计算最优优惠

### 非目标（明确不做的事）

- 不做优惠券分享裂变功能（如分享得券、助力领券）
- 不做优惠券与其他营销活动（满减活动、秒杀）的叠加规则引擎
- 不做优惠券的跨平台通用（仅限本平台使用）
- 不做优惠券的视觉模板设计（仅做数据与逻辑，前端展示另排）
- 不做优惠券的财务对账报表（归财务系统）

## 功能需求

### FR-1: 优惠券创建
- **描述**: 运营人员通过后台创建优惠券，支持满减券、折扣券、新人券三种类型，配置面额、门槛、有效期、库存等参数
- **优先级**: P0
- **触发条件**: 运营人员在后台点击"创建优惠券"并提交表单
- **预期行为**: 系统校验参数合法性后持久化优惠券模板，状态为"未发放"；满减券需配置满减门槛与面额；折扣券需配置折扣率（1-99%）与最大优惠金额；新人券需配置新人判定规则
- **边界条件**: 面额必须 > 0；折扣率 1-99；有效期开始时间 < 结束时间；库存 1-1000000；同一名称券不允许重复创建

### FR-2: 优惠券批量发放
- **描述**: 运营人员按用户标签、注册时间、消费金额等条件筛选目标用户，批量发放优惠券
- **优先级**: P0
- **触发条件**: 运营人员在后台选择券模板 + 筛选条件 + 发放数量，点击"发放"
- **预期行为**: 系统异步执行发放任务，写入用户券表（status=未使用），扣减券模板库存；发放完成后通知运营人员结果（成功数/失败数）
- **边界条件**: 单次发放上限 10000 张；目标用户数 > 库存时部分发放并记录失败原因；同一用户同一券模板限领 1 张（除非配置允许多领）

### FR-3: 用户领券
- **描述**: 用户在领券中心主动领取可用的优惠券
- **优先级**: P0
- **触发条件**: 用户在领券中心点击"领取"按钮
- **预期行为**: 系统校验券状态（进行中）、库存（>0）、用户资格（新人券校验是否新人）后，原子扣减 Redis 库存并写入用户券记录；返回领取成功
- **边界条件**: 库存不足返回"已领完"；新人券非新人领取返回"不符合资格"；同一用户重复领取返回"已领取"；券状态非"进行中"返回"活动已结束"

### FR-4: 优惠券核销
- **描述**: 用户下单时选择优惠券，系统校验并计算优惠金额，订单支付成功后核销优惠券
- **优先级**: P0
- **触发条件**: 用户下单时选择优惠券并提交订单
- **预期行为**: 系统校验券有效性（属于用户、未使用、未过期、满足门槛）后计算优惠金额；满减券按"满 X 减 Y"计算；折扣券按"折扣率 × 金额，不超过最大优惠"计算；新人券额外校验订单是否首单；订单支付成功后更新券状态为"已使用"
- **边界条件**: 订单金额不满足满减门槛时不可用；折扣券优惠金额 > 订单金额时按订单金额计；订单取消/退款时券回退为"未使用"（仅未过期券回退）；同一订单同类券仅可用 1 张

### FR-5: 优惠券过期处理
- **描述**: 系统自动将超过有效期未使用的优惠券标记为"已过期"，并释放占用
- **优先级**: P1
- **触发条件**: 定时任务每 5 分钟扫描过期券；Redis Key 过期事件触发前置清理
- **预期行为**: 扫描到 expire_time < now() 且 status=未使用 的用户券，批量更新为"已过期"；记录过期日志；释放 Redis 库存占用（如适用）
- **边界条件**: 已使用/已核销的券不处理；扫描失败时下次扫描补偿；单次扫描批量上限 1000 条防止锁表

### FR-6: 优惠券记录查询
- **描述**: 客服人员按用户 ID 查询其优惠券领取与核销记录，用于客诉处理
- **优先级**: P1
- **触发条件**: 客服在后台输入用户 ID 查询
- **预期行为**: 返回该用户所有优惠券记录（含券模板名称、类型、面额、状态、领取时间、核销时间、关联订单号），支持按状态筛选与分页
- **边界条件**: 仅查询最近 90 天记录；单次查询上限 100 条；无记录时返回空列表

## 非功能性需求

### 性能

- 领券接口 P99 ≤ 100ms，QPS ≥ 1000
- 核销接口 P99 ≤ 150ms，QPS ≥ 500
- 过期扫描任务单次执行 ≤ 30s
- 优惠券记录查询 P99 ≤ 200ms

### 安全

- 优惠券创建/发放仅运营角色可操作（RBAC 鉴权）
- 领券接口限流：单用户 10 次/分钟，单 IP 100 次/分钟
- 优惠券模板配置变更需审计日志
- 防刷：领券接口接入设备指纹识别

### 可维护性

- 优惠券库存扣减与核销关键指标接入 Prometheus 监控（扣减成功率、核销量、过期量）
- 优惠券相关日志统一 traceId 串联（领券→核销→退款回退全链路）
- 优惠券类型扩展无需改核心代码（策略模式）

## 依赖与前置条件

- 依赖 Redis 5.0+（库存扣减）
- 依赖 XXL-Job 调度中心（过期扫描任务）
- 依赖现有订单服务 OrderService（核销对接）
- 依赖现有用户服务 UserService（新人资格判断）
- 前置数据：用户标签数据已就绪（用于批量发放筛选）

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 高并发领券导致超发 | 中 | 高 | Redis Lua 原子扣减 + DB 乐观锁兜底 + 异步对账 |
| 新人券并发领取一人多领 | 高 | 高 | 用户维度分布式锁 + 唯一索引兜底 |
| 过期扫描任务卡死影响线上 | 低 | 中 | 分页扫描 + 超时熔断 + 告警 |
| 优惠券核销与订单事务不一致 | 中 | 高 | 本地事务 + 幂等键 + 对账补偿任务 |

## 验收标准

- [ ] 运营人员可创建满减券、折扣券、新人券三种类型，参数校验生效（FR-1）
- [ ] 运营人员可按条件批量发放优惠券，发放结果可查询（FR-2）
- [ ] 用户可在领券中心领取优惠券，库存不足/资格不符/重复领取有明确提示（FR-3）
- [ ] 用户下单时选择优惠券，系统正确计算优惠金额（满减/折扣/新人三种逻辑均验证通过）（FR-4）
- [ ] 订单取消/退款后未过期的券回退为"未使用"（FR-4）
- [ ] 过期券在 5 分钟内被自动标记为"已过期"（FR-5）
- [ ] 客服可按用户 ID 查询优惠券记录，支持分页与状态筛选（FR-6）
- [ ] 领券接口压测 P99 ≤ 100ms，QPS ≥ 1000，零超发（性能验收）
- [ ] 优惠券类型扩展（如新增"兑换券"）无需修改核心核销逻辑（可维护性验收）
